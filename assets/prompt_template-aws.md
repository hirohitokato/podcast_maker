# 目的

このコンテンツの目的は、AWSサービスの仕様を網羅的に説明することではありません。リスナーが会話を聞き終えたときに、

* このAWSサービスが何をするものなのか
* どんな場面で使うのか
* なぜその場面で役立つのか

の3点を直感的に理解できることを目指してください。同時に、一般的な英会話教材としても自然で楽しい会話にしてください。

# 想定リスナー

* 英語レベル: CEFR A2〜B1程度
* IT・クラウドの基礎知識はある
* AWSについては初級〜中級
* 技術英語と日常英会話を同時に学びたい人

# 台本構成

必ず以下の流れで会話を構成してください。

1. 日常的なシチュエーションから会話を開始する
2. 登場人物の一人が、そのシチュエーションに関連する「困りごと」や「疑問」を話す
3. もう一人が、その問題をAWSサービスに例える
4. AWSサービスの主要な機能を説明する
5. 実際のシステムではどのような用途で使われるかを説明する
6. 分かりやすい日常的な例えを使って理解を補助する
7. 会話の最後で、冒頭のシチュエーションを回収した軽いジョークまたはオチを入れる

説明だけの講義にならないようにしてください。AWSの説明は必ず2人の自然な会話の中で行ってください。

# シチュエーション

英会話教材でよく使われる、日常的で理解しやすいシチュエーションを使用してください。

例:

* カフェ
* レストラン
* 空港
* ホテル
* スーパーマーケット
* オフィス
* 電車
* 旅行
* 引っ越し
* パーティー
* オンラインショッピング
* 荷物の配送

AWSサービスの特徴を自然に説明できるシチュエーションを選択してください。
毎回必ず同じシチュエーションを使用する必要はありません。

# AWSの説明ルール

AWSサービスについては、以下の3点を必ず会話の中で説明してください。

1. What it is: そのAWSサービスが何をするサービスなのか
2. When to use it: どのようなユースケースで利用するのか
3. Why it is useful: そのサービスを利用すると何が便利なのか

ただし、すべての機能を説明しようとしないでください。
この短いエピソードで最も重要な機能またはユースケースを1〜2個に絞ってください。
必要以上に細かい設定値、API仕様、料金体系などには踏み込まないでください。

# 技術的正確性

AWSについての説明は、必ず現在のAWS公式情報を根拠にしてください。

優先する情報源:

1. AWS公式サービスページ
2. AWS公式ドキュメント
3. AWS Architecture Center
4. AWS Decision Guides
5. AWS Well-Architected Framework

AWS公式情報で確認できない内容を事実として追加しないでください。
サービスの仕様、制限、料金、リージョン対応など、変更される可能性が高い内容は、台本の中心的な説明には使用しないでください。
比喩は理解を助けるために使用して構いませんが、比喩と実際のAWSの仕様を混同しないようにしてください。

# 英会話ルール

会話は2人だけで行います。Speaker A と Speaker B は、それぞれ異なる性格を持たせてください。

例えば、

* Speaker A: curious / practical
* Speaker B: knowledgeable / playful

のような組み合わせです。一人が一方的に長く説明し続けないようにしてください。

1回の発言は原則として1〜3文程度にしてください。自然な相づち、質問、軽い驚き、ジョークなどを含めてください。

以下のような自然な表現を適度に使用してください。

* Really?
* Exactly.
* That makes sense.
* Think of it like...
* Pretty much.
* So basically...
* Wait, does that mean...?

ただし、毎回同じ表現を使用しないでください。

# 英語レベル

* CEFR A2〜B1程度の平易で自然な英語を使用してください。
* AWSの正式なサービス名や一般的なIT用語はそのまま使用してください。
* 難しい単語を多用しないでください。
* AWS特有の専門用語を使用する場合は、会話の中で意味が推測できるようにしてください。

# 長さ

会話部分の読み上げ時間は約70～90秒にしてください。

目安として、

* dialogue内の英単語数: 190～230 words

を目標にしてください。

AWSサービス名や固有名詞も通常の単語としてカウントしてください。長さよりも会話の自然さを優先しますが、極端に範囲を外れないようにしてください。

# オチ

最後の1〜3発言では、必ず軽いオチを入れてください。

オチは、

* 冒頭のシチュエーション
* 会話中に登場した例え
* AWSサービスの特徴

のいずれかを回収してください。ただしAWSの専門知識がないと理解できないジョークにはしないでください。
英会話教材として自然な、軽く笑える程度のオチにしてください。

# 内容チェック

出力前に内部で以下を確認してください。

* AWSサービスの説明は技術的に正確か
* AWSの主要な用途が理解できるか
* 日常的な例えがAWSの概念と矛盾していないか
* 会話が講義になっていないか
* Speaker A / Speaker B の発話量が極端に偏っていないか
* dialogueの英単語数が約230〜270 wordsに収まっているか
* 最後にオチがあるか
* JSONが指定されたSchemaに完全に適合しているか

問題がある場合は修正してから出力してください。
